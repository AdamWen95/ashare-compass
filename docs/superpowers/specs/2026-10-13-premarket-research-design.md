# 每日 09:00 盘前研究简报设计

> 2026-10-14 用户修正：下文v1中“任一资料不足即按兵不动”的规则已由[证据分量v2决策](../../PREMARKET_EVIDENCE_ADR.md)替代。按已有有效资料判断，缺失项单列；新报告为premarket-brief-v2、姿态为premarket-stance-v2，旧v1冻结报告不重算。其他未冲突边界继续生效。

状态：用户于 2026-10-13 审阅后明确要求进行实施；功能方案及书面规格均已确认。

适用范围：AShare Compass，沪深普通 A 股，个人只读研究，3–10 个交易日短线波段。

本文件是设计，不表示功能、数据源、调度或部署已经完成。服务器配置和本轮现场证据仅进入被忽略的 `.local/`，不写入本文件。提交、推送或创建 Git 历史须按当前会话的明确用户授权执行。

## 1. 用户目标与已经确认的决策

每天北京时间 09:00，打开现有网页即可看到面向最近一个尚未开盘交易日的研究简报，回答：

1. 市场姿态：进攻、减仓防守、按兵不动；为什么如此判断，哪些证据与判断相反。
2. 重点方向：昨日强势的哪些行业值得延续观察，隔夜消息带来了哪些新的研究方向。
3. 关注股票：最多 5 只；为什么关注、技术评分构成、消息关联、主要风险、观察及失效条件。
4. 相比上期：姿态、方向、候选及风险发生了什么变化，变化由哪些新证据引起。
5. 数据状态：行情日期、消息截点、生成时间、覆盖范围和未核查事项。

采用“确定性规则作判断、技术评分排列研究优先级、模型解释有来源的消息”的方案。单纯按总分选股不能覆盖隔夜风险；完全由模型选股缺少可复核的计算过程。

“减仓防守”是面向整体市场的风险倾向，不假定用户实际持仓，不生成账户级买卖、数量、仓位比例、成交或收益。本次授权允许上述市场姿态和研究推荐，并替代旧文档中与其直接冲突的盘后定位；账户、券商与执行交易等边界继续保留。

## 2. 时间口径与每日流程

### 2.1 必须独立保存的日期和时间

| 字段 | 含义 |
| --- | --- |
| `report_date` | 本次早报发布的自然日，北京时间 |
| `target_session_date` | 面向的交易日：交易日早晨为当天；休市日为下一个可信交易日 |
| `market_as_of_date` | 09:00 之前最近一个已完整收盘的交易日 |
| `planned_start_at` | 当天 08:30 |
| `news_cutoff_at` | 当天 08:55，表示纳入信息的最晚可用时刻，不代表所有来源都更新到此时 |
| `publication_due_at` | 当天 09:00 |
| `actual_started_at / generated_at / published_at` | 实际开始、生成、发布时刻，不得回填为计划时刻 |

原始来源还分别保存业务有效日期、来源发布时间及精度、实际采集时间、首次观察时间、内容版本和哈希。上一个收盘日行情在本日盘前使用是正常盘前研究；不能仅因采集日期晚于行情日期，把整份早报误标为历史补跑，也不能抹去原始输入已有的历史重建属性。

交易日关系必须由可信日历推导。日历范围不覆盖目标或发现冲突时发布“交易日待核验”，不得按星期推断；已有受审日历的到期边界必须保留。

### 2.2 单一日任务的阶段与截止

| 阶段 | 时间约束 | 产出 |
| --- | --- | --- |
| 行情准备 | 08:30 启动，最晚 08:50 结束 | 昨日完整行情、市场截面、行业集合、技术预选及这组股票的财务证据 |
| 隔夜信息更新 | 行情阶段后执行；最晚 08:55 冻结 | 来源健康、政策与公告材料、每个来源实际覆盖窗口 |
| 解释与决策 | 冻结后，最晚 08:59 结束 | 有引用的事件、规则判断、候选卡片与数据缺口 |
| 发布 | 09:00 对读者可见 | 完整简报或明确的降级/失败状态 |

阶段预算包含排队、登录、重试、解析和归档；子阶段不重新获得整轮预算。预留发布时间，不让行情耗尽全部时间。提前完成时保存不可见的草稿，到发布时点才更新可读指针；不另设第二个生产日任务。

09:00 是服务目标，不伪装成绝对可用保证。运行中有状态记录供网页读取；若任务或服务器失效，网页必须表明“今日未生成/已超时”，不能把上一期显示成今天已更新。08:30 前的定时执行返回未到时间；09:00–09:15 的首次恢复运行可以在剩余预算内补发并标为迟到；09:15 起定时补发停止，不发起新的模型请求，手工补跑仍明确记录实际时间。

单一任务替换现有 21:00 计划。保留既有任务身份、锁和预算存储；不同时启用第二套早报、夜报或 Codex 聊天自动化。

### 2.3 休市日和消息窗口

每天仍有 09:00 版面。休市日发布“休市资讯与下一个交易日观察准备”，更新新消息，引用最近收盘日的技术背景，不假装存在新的日线或当天可交易。

新消息窗口从上一期成功冻结的消息截点开始；首次运行最多回看 3 个自然日。周末和长假保留未失效的历史背景，并按真实首次观察时间区分“本期新增”和“持续背景”。连续失败可有界回看至 14 日，超过范围显示覆盖缺口。重复、修订、撤回材料以原文 URL、发布者、版本和哈希去重，不将旧消息反复称作新催化。

## 3. 行情与资格：盘前不能复用错误的日期假设

当前行业、行情和资格链路围绕同一个盘后目标日建立绑定。新流程要分别绑定本日观察到的证券名单、上一完整交易日的行情、以及截至盘前的状态证据；不能通过修改时间戳让三者看起来同日。

- 优先复用已验证、覆盖 `market_as_of_date` 的冻结日线和行情截面；不足部分按现有许可和有界策略增量准备。
- 盘前网页报价只有业务日期、时间及数值校验通过，才能解释为上一日收盘。不能假定 08:30 抓到的内容一定是昨收盘；更新中的报价、缺少日期或冲突输入明确拒绝。
- 没有可验证全市场截面时，不用候选行业的股票代替全市场计算上涨家数占比，不通过批量补抓全市场多年日线补洞。
- 非 ST、上市状态、证券身份、非停牌、行情完整性和原量价门槛继续保留。退市整理期仍不作为新增资格门槛。
- 昨日非停牌不能冒充本日非停牌。盘前状态未知时，在个股显示“本日交易状态待核验”，不能声称开盘一定可交易。
- 市场环境基准必须独立于“有无入选行业”：即使零行业、零候选，也应能够判断市场环境，或明确说明所缺输入。

首次切换前须用受控的真实盘前样本验证报价的日期语义。若不支持，先报告这一数据障碍并保留原生产调度；不能仅凭离线测试把定时器切换后等待失败。

## 4. 市场姿态：独立规则，不由个股总分决定

规则版本拟为 `premarket-stance-v1`。初版阈值是明确可审查的研究启发式，不是经过历史验证的盈利规则；不得展示胜率或概率。

### 4.1 必需输入

1. 可信的交易日关系。
2. 对最近完整交易日完成校验的沪深普通 A 股行情截面；去重后计算上涨家数占比，平盘计入分母，有证据的全天停牌剔除；缺失、身份冲突和排除分别计数。
3. 上证综指连续 21 个可信交易日日线：用于 MA20、前一日 MA20、5 日变化和成交额比较。数值由代码计算，指数成交额只称为指数口径，不冒称沪深全市场成交额。
4. 已配置的必要政策与监管来源完成本期有界采集。覆盖状态为 `ready / partial / unavailable / not_enabled`；`ready` 仅表示声明的来源和窗口成功，不等于市场全部消息。

有影响判断的时间或哈希冲突直接阻断决策。市场截面必须完整才能宣称“全市场”指标；不完整时展示有效样本及覆盖比例，并输出资料不足。

### 4.2 有序决策表

先检查输入，再按以下优先级决定唯一姿态：

| 条件 | 姿态 | 原因类型 |
| --- | --- | --- |
| 任一必要输入未知、过期、缺失或无法验证 | 按兵不动 | 资料不足；同时展示已知风险 |
| 指数收盘低于 MA20，且全市场上涨家数占比不高于 40% | 减仓防守 | 趋势与市场广度同时偏弱 |
| 上涨家数占比不高于 30%，且市场个股涨跌幅中位数低于 0 | 减仓防守 | 下跌扩散 |
| 指数收盘高于 MA20、MA20 不低于前一日、指数 5 日变化为正；上涨占比至少 60%；指数当日成交额不低于此前 5 日均值；存在合格关注方向；没有未解决的重大反面事件 | 进攻 | 趋势、广度、活跃度与方向共同支持 |
| 其余情况 | 按兵不动 | 信号分歧或中性 |

边界数值用精确十进制比较，显示舍入不参与判断。零分母和无法计算保留未知。

消息解释不能单凭“利好”把弱势市场升级为进攻。经过原文、主体和适用范围核验的反面事件，可以取消进攻资格并转为“按兵不动—事件待确认”；不能凭模型自由文本直接生成减仓指令。每个姿态包含支持证据、反面证据、影响范围和下一次判断将发生变化的条件。

“主情景”只能表达由上述证据支持的条件式预期，例如趋势维持时延续观察；“反情景”列出已有反面证据及失效条件。不能把今天已观察到的强弱写成明日必然走势，也不在没有计算依据时添加置信百分比。

## 5. 行业方向与股票推荐

### 5.1 方向分为两类

- **量价方向**：最多 3 个，复用原行业规则，用上一完整交易日的强弱和上涨广度支持。只有与上一期可比观察一致时，才写“延续”；首次出现写“新进入观察”，不直接称为真实资金轮动。
- **事件方向**：最多 2 个，由截点内可信原文及有版本的行业关联支持。与量价方向重合时合并证据；尚未进入量价研究集合的方向显示“事件关注，待行情确认”，不虚构对应个股资格。

模型提到行业或公司只是待核查的关联提案。名称命中、同属一个宽泛行业或集团名称，不足以证明具体上市公司受益。沿用现有主体/业务关联能力，保留原文片段和别名、母子公司、否定与时点检查。

### 5.2 技术评分的明确用途

保留现有七组技术指标及逐项加减分计算，数值名称仍为“技术评分”。它不包含政策、财务、消息完整性或市场环境，不包装成“综合胜率”。

新决策输出使用独立版本 `premarket-recommendation-v1`，允许技术评分影响新早报关注顺序；原冻结报告的 `shadow_only` 契约及排序不改写。新输出记录 `score_used_for_priority=true` 和规则版本，不能继续写“评分不影响排名”。

推荐池来自**全部量价及资格合格记录**，不能先截取旧排名前 20 或前 5 再重排。缺失评分不补 50 分或 0 分；归入待核查，不与有效分数混排。

排序步骤固定为：

1. 先检查证券与量价资格，处理当前已核验的重大公司风险；风险未知与已证实不利分开。
2. 先按量价方向名次确定技术预选优先级；最终事件核验可以将方向或股票降为待核查、取消关注，并补充支持理由。初版不为模型判断的“利好”另加任意分数。
3. 同一方向内按技术评分降序，其次按 20 日相对上证表现、20 日平均成交额降序，最后按证券 ID 稳定排序。
4. 按方向优先级轮流选取，每个方向最多 2 只，总数最多 5 只；同一股票去重，少于上限不补凑。

“重点关注”要求本期需要的公司材料检查完成且无未解决重大风险。量价合格但公司资料不完整的股票进入独立的“待核查观察”，可保留技术分和研究理由，但不冒充已充分核查的推荐。防守或资料不足时，保留观察名单，同时明确“本期不建议据此新增进攻”，不强制输出推荐股票。

现有财务采集最多核查 5 只。08:50 前从全部合格记录形成最多 5 只技术预选并准备财务资料；随后新闻阶段优先检索这组股票的公告。最终事件核验对预选名单进行保留、降级或否决，被否决后不追加新一轮财务/公告核查来补足 5 只。盘前新增事件涉及预选以外的股票时，只能列入待核查观察；不能凭新闻绕过资格和公司核查。保留每只股票的筛选和排除原因，不能在预算耗尽后称整个合格池已做公司核查。

### 5.3 每张股票卡片

名称及代码；所属方向；“重点关注/待核查”；当前市场姿态；技术评分与构成；2–3 条可溯源关注理由；关联消息及其性质；反面证据；交易状态时间；观察条件与失效条件。

观察条件是条件式研究结论，不是已经发生的事实。09:00 报告没有当天集合竞价和开盘走势，不能声称已经放量突破或已获竞价确认。不输出买入价格、数量或目标收益。

## 6. 隔夜消息：补来源，同时保留许可和覆盖状态

### 6.1 来源能力矩阵

| 类别 | 当前已核对状态 | 新版要求 |
| --- | --- | --- |
| 商务部原创新闻及政策 | 现有配置已启用两类来源 | 保留，作为贸易及相关政策背景，不代表全市场覆盖 |
| 综合政策与货币政策 | 新来源尚未验收 | 核对国务院和央行原创栏目；逐项登记采集、缓存、模型使用和摘录权限 |
| 证券监管与交易所通知 | 新来源尚未验收 | 核对证监会与沪深交易所原创公告，识别实施日期及适用范围 |
| 候选公司公告 | 尚无满足盘前核查要求的已验收流程 | 通过获准的披露来源按证券身份和窗口检索；记录分页截断与正文不可用 |
| 海外市场、汇率、期货 | 当前没有已验收的综合接入 | 明确列为未覆盖，不承诺“覆盖全部隔夜动态” |

新增来源没有通过访问方式、字段、时点、范围、许可和小样本验证前保持禁用。网页可公开访问不等于已获得自动化、外发模型或全文再分发许可；不得把搜索结果当作程序已接通的数据源。

生产切换的最低消息条件是：至少有可用的综合/货币政策背景、证券监管来源，以及对最终关注股票可说明覆盖范围的公司公告检查。可以完成本地实现和离线验收，但最低条件未达成时不得声称完整功能上线，亦不自动替换生产调度。

2026-10-13 检索到的原站声明核验入口：

- [商务部网站声明](https://www.mofcom.gov.cn/fzlm/wzsm/index.html)。
- [中国政府网网站声明](https://big5.www.gov.cn/gate/big5/www.gov.cn/home/2014-02/23/content_5046258.htm)。
- [证监会法律声明](https://www.csrc.gov.cn/csrc/c100227/common_zcnr.shtml?channelid=45858a464a684b16935e5dc0d5779dbd)。

这些入口只用于核验，不构成新来源已获准使用的结论。央行采购子站声明不能代替央行新闻主站规则，巨潮上某家公司 PDF 的声明不能代替平台规则。

### 6.2 事件数据与模型职责

事件保存原文定位、发布者、原始 URL、发布时间及精度、首次观察时间、内容哈希、事件类型、生效时间、命名主体、潜在影响方向、支持片段、反面片段及未确认事项。

事实和推论分开。模型仅对允许外发的文字作提取和有引用的解释，输出候选事件与关系；本地校验器核对引用、主体、允许的实体及时间后，才进入决策输入。模型不能凭记忆补事实，不能执行网页指令，不能新增抓取网址或调用工具。

行情、派生技术指标、技术分、账户信息和财务接口原始数据继续留在本地。行业和证券身份关联在本地完成，不能为使模型选股而默认开启行情外发。

保留既有模型每任务最多 2 次、每日最多 6 次、自动重试 0 的上限；新增模块共享同一预算。新闻 HTTP 总预算维持现有每轮最多 20 次并计入失败和重试，新来源共享预算而非各自获得 20 次。最终来源较多时显示本轮未覆盖项目，不隐藏截断。

## 7. 结构、接口与持久化

新业务集中在 `src/ashare_daily/premarket/`，按职责拆分；新增手写文件不超过 500 行：

- `contracts.py`：日期、市场状态、事件、决策、报告的边界模型及枚举。
- `timing.py`：可信交易日解析、阶段截止、迟到/休市规则。
- `market.py`：已冻结输入校验及市场广度、指数指标，不承担文本解释。
- `events.py`：消息窗口、引用和本地行业/公司关联校验。
- `decisions.py`：姿态状态机、方向优先级和候选排序，纯计算，不联网。
- `report.py`：早报结构、理由与缺口展示、不可变发布。
- `operations/premarket.py`：单任务编排、共享锁/预算、阶段状态、截止取消及降级。

复用既有来源登记、归档、行情校验、证券资格、指标计算和预算接口。新消息适配器放入既有来源层，不混入决策模块；已有函数确实通用时提取必要部分，不复制整条旧流水线。

现有 `run-daily --config config/sector_observation_daily.json --scheduled` 仍是正式入口；配置用新的 workflow/version 表达盘前时间语义，不能简单放宽旧“必须 21:00”校验而不改日期契约。公开旧 CLI 与旧报告阅读兼容按外部契约保留；不新增两个并行活跃的内部推荐实现。

报告契约为 `premarket-brief-v1`，至少包含 `edition_id`、以上时间字段、`stance`、`directions`、`focus_candidates`、`pending_candidates`、`overnight_events`、`changes_since_previous`、`coverage`、`rule_versions`、输入哈希及预算摘要。

新报告按发布日和唯一 ID 保存，旧报告不迁移、不重写。网页读者按 schema 分派，日期导航使用发布日；同时显示行情日和目标交易日。发布采用验证后的临时目录与原子指针更新，避免一半新文件、一半旧文件。

预算数据库沿用原表和账目，本阶段不引入账户或业务数据迁移。阶段状态、任务身份和发布身份写入新的不可变任务记录；定时尝试按实际北京时间自然日累计，最多 2 次，不能因 workflow 改名重置。唯一实例锁覆盖整个任务；重启先核对已消耗预算和已有发布，不重复创建模型请求。

## 8. 前端与导出

首页顺序：今日姿态与核心理由 → 隔夜重要变化 → 重点方向 → 最多 5 张股票卡片 → 风险与数据缺口。完整筛选、评分构成和原文证据继续可展开。

姿态使用文字及图标共同表达，不能仅靠颜色。证据链接指向已冻结的来源记录或原文，并对文本和链接做安全渲染。所有金额、百分比、百分点与数据日期沿用正确口径。

状态必须覆盖：准备中、准时发布、迟到、休市、零候选、数据不足、模型不可用、整轮失败、已有旧报告但今日尚未生成。刷新不能把上期内容当成本期完成；异步结果按 edition 校验，防止过期返回覆盖新状态。

HTML、Markdown、JSON 和网页读取同一报告模型，标题统一为“盘前研究简报”。历史盘后报告保留原标题和规则说明。

## 9. 验证与上线门槛

| 验收项 | 必需证据 |
| --- | --- |
| 日期正确 | 普通交易日、周一、长假首日、周末、跨年未覆盖、未来截点和补跑测试 |
| 09:00 语义 | 可控时钟验证各阶段截止、提前草稿、迟到和 09:15 后停止；不得真实等待半小时测试 |
| 市场姿态 | 每条决策路径及阈值边界；缺失数据不能进攻；候选样本不能冒充全市场 |
| 评分推荐 | 全部合格记录参与排序；缺分、同分、多行业、重复股票、风险否决、零候选及预算内核查 |
| 消息安全和时点 | 伪引用、未来信息、只有标题、同名公司、母子公司、否定、撤回修订、未知许可、提示注入 |
| 预算和幂等 | 多阶段共享上限、超时结果未知、进程中断、已有报告复用、任务版本变化不重置预算 |
| 历史兼容 | 原冻结报告哈希不变、旧辅助分声明不改写、旧阅读/导出正常 |
| 网页 | 真实浏览器检查姿态、卡片、空/失败/旧报告状态、证据展开和导出 |
| 数据接入 | 每个新增来源有独立小样本记录；真实盘前行情日期单独核验 |
| 研究效果 | 3/5/10 个交易日的事后跟踪框架；未成熟样本不计算结果，不把描述性观察当作可成交回测 |

技术评分对照保留原相对强弱顺序作为基线，记录候选重叠、后续价格变化及不利变化；逐日冻结避免未来信息。旧 5/20 日历史重建只能作为参考，不能冒充新 3–10 日策略验证。不以“离线测试通过”宣称推荐有效。

完整上线需同时满足：相关离线检查通过、必要来源验收完成、盘前日期语义验收完成、报告读者/导出兼容、配置与回退材料完成。上线后第一次自然 09:00 运行单独验收；部署成功不等于早报已经准时生成。

## 10. 发布与恢复

仅从当前仓库维护；保护工作区已经存在的深交所导出及依赖改动，不覆盖、不提交。公开设计、规则和通用文档随代码维护，服务器细节只写入 `.local/`。

发布前复核实际服务、任务是否运行、锁和数据状态；保存必要文件及现有 unit 的精确备份。先发布和验证新版应用，再调整**现有** timer 至 08:30，确认不存在额外 21:00 任务。保留访问范围和 `.env`，不得使用固定旧名称的模板覆盖实例。

回退同时恢复应用文件、正式配置和原 timer；新早报文件保留，不清空数据库或历史记录。旧应用不能读取新 schema 时，应将最新指针恢复至旧格式可读版本，保留新记录供后续复查。预算、尝试和锁的历史不能随应用回退恢复到旧副本。

后续实施需同步 `AGENTS.md` 的项目段、`docs/00_SCOPE_CHANGE.md`、`README.md`、使用指南和参考评分文档，准确表达新的范围及版本。当前设计阶段不修改这些生效约束，也不改生产调度。

## 11. 设计自查与实施交接

本规格已明确用户周期、默认范围、输入与时间语义、状态优先级、排序、预算、来源验收条件、兼容与回退。新增来源尚未验收被定义为明确的发布前置条件，不使用“默认可用”的隐含假设。

书面规格审核时，重点检查第 4 节姿态阈值、第 5 节推荐逻辑，以及第 6 节覆盖范围。阈值改变需要新规则版本；历史报告永不回填。

规格获批后编写实施计划，按时间契约与报告模型 → 市场/评分决策 → 隔夜来源与事件 → 编排与页面 → 受控验证与部署组织任务；源接入验证可提前进行，但不越过来源权限和次数边界。
