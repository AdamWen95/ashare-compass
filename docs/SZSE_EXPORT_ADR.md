# ADR：以官方整表导出采集深交所A股名单

状态：采用。合同核对日期：2026-10-12。

## 依据和决定

深交所JSON名单逐页获取会产生较多请求，单页连接中断可能使整轮名单不完整。AKShare的 [stock_info_sz_name_code](https://github.com/akfamily/akshare/blob/main/akshare/stock/stock_info.py) 使用同一官方报表的Excel整表下载。本项目独立实现该获取方式，不引入AKShare整体依赖、不更换数据供应商、不采用静态名单或指数成分股代替完整范围。

正式入口仍为深交所公开A股列表：`CATALOGID=1110`、`TABKEY=tab1`。读取顺序为JSON第一页、官方XLSX导出、JSON第一页。只访问已登记的深交所来源；权限拒绝或限流仍停止该源，继承现有请求、重试和整轮时间上限。下载前后记录数、页数、日期、列合同、行业字典及首批记录必须一致。工作簿实际行数必须等于接口记录总数，代码唯一、板块明确、关键字段齐全且上市日期有效。

每轮导出使用不同的数值型 `random` 参数，不沿用示例中的常量缓存键；请求要求缓存重新校验，并保存源端Cache-Control/Age供诊断。前后元数据是同一来源的一致性约束，不构成独立来源核验，也不能保证源站从未发布陈旧内容。

本方案参考AKShare的官方导出路径，并非声称AKShare能够授予上游数据权限。东方财富路径的许可状态和关闭配置不变，相关行情调用不是本变更的一部分。

## 冻结证据与兼容

每次原始HTTP响应和原始字节分别保存。新增 `szse-export-bundle-v1` 仅作为三份证据的索引，记录各回执的文件哈希，不制造JSON分页响应。一个工作簿是一个交付单元，名单内部的 `expected_pages=1` 对应该单元；原JSON源声明的页数另存 `source_expected_pages`，总记录数仍来自源端元数据。

行业分类重读证据索引、三份HTTP回执、原始Excel、前后元数据及原始Universe快照，校验全部文件哈希、来源身份和日期，重新解析每条记录，再核对成员原始字段和行业枚举。旧JSON分页归档继续按原合同读取，不回填或覆盖旧报告。公开名单配置新增 `szse_list_format`，缺省 `json_pages` 保持既有配置行为，当前沪深配置显式使用 `xlsx_export`。

## 文件处理与维护

Excel解析使用固定 `openpyxl==3.1.5` 和 `et-xmlfile==2.0.0`，不升级其他依赖。实际官方导出可能错误声明单元格范围为 `A1:A1`；解析读取实际行，再与独立元数据总数核对。仅接受单个“A股列表”工作表，检查压缩及展开大小、重复压缩成员、必需列、公式和外部链接，拒绝损坏或非预期文件。

下载时不重建股票池或推断缺失行。Excel缺少独立日期标记时，日期依据明确标记为前后元数据绑定的当日观察，不当作独立历史快照，也不视作独立供应商交叉验证。

无数据库迁移。发布顺序为新增锁定依赖、适配器和行业读取器、配置。恢复时同时恢复源码和配置；新增证据保留原字节，旧版本无法读取的新格式明确拒绝，不能转换成旧JSON响应。必要时仅卸载本次新增依赖。

## 验收边界

分别验证真实服务器HTTP、下载日期和完整性、冻结文件离线回放、名单与行业流程回归。一次完整名单成功不能证明后续行情、模型或整份简报已成功，须单独核对自然任务结果。
